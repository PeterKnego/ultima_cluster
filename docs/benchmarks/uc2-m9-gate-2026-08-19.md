## What the gate measures

Spec: `docs/superpowers/specs/2026-08-19-uc2-production-readiness-design.md` §4.
Plan: `docs/superpowers/plans/2026-08-19-uc2-m9-deployable-node.md`.

M9 makes the node **deployable**: a real `uc2-node` binary that starts from a
config file, refuses a misconfiguration at startup instead of failing later in
a way that looks like something else, and stops cleanly on `SIGTERM` so a
restart rejoins from the journal rather than paying reconstruction.

M9 changes no consensus, wire-protocol, or cnc-page surface. It is additive:
new modules and binaries plus one new method on `Node`. That is why this gate
measures **operational cost and refusal behaviour**, not safety — safety is
already held by the sim, the lincheck capstones, the crashtest, and the Lean
proofs, and none of those are weakened by a milestone that adds a `main`.

## The bar

Pre-committed. Four rows, all must pass.

| # | Measure | Bar |
|---|---|---|
| 1 | `SIGTERM` → process exit, leader under sustained load | **< 1 s**, exit code **0** |
| 2 | Snapshot install on restart | cnc `incoming_snapshot_pos` (offset 1280) **unchanged** across the stop+restart cycle |
| 3 | Cluster commit-rate dip across the stop+restart window | **< 10 %** |
| 4 | Config refusals | every preflight rule refuses with a message **naming the offending field** |

### Why each row is the right bar

**Row 1 — under load, not idle.** A drain measured on a quiescent node proves
nothing: the archive has nothing to catch up on. The stop must be issued while
the node is the serving leader taking writes, which is when the archive is
furthest behind. 1 s is the operational bar — a supervisor's stop must not feel
like a hang — and it must be met with the drain's default 5 s budget available,
so a PASS means the drain *finished*, not that it timed out.

**Row 2 — the row that makes the drain worth having.** A node that stops
cleanly holds every acked byte in its journal, so on restart it replays a short
tail. A node that did not drain may fall behind the leader's purge floor and
have to be served a **snapshot** instead. `incoming_snapshot_pos` is the
evidence: it moves only when a snapshot session is installed. Unchanged across
the cycle means the restart cost was replay, not reconstruction. This is the
one row that would catch a `stop_draining` that silently degraded to `stop()`.

**Row 3 — the M6/M7 dip bar, unchanged.** A planned leader stop costs one
election timeout (150–300 ms) because M9 deliberately ships **no leadership
transfer** — that is a consensus change and is out of scope. Reusing the
established 10 % bar keeps this comparable to the M6 learner-join dip (0.9 %)
and the M7 transition dips (0.0–4.7 %). A dip materially worse than those means
the clean stop cost more than the election it was supposed to cost.

**Row 4 — refusals are a feature, so they are gated.** M9's premise is that a
named startup refusal beats a confusing downstream failure. That premise is
only true if the refusal actually names the field. Each rule is driven with a
config that violates exactly it, and the message is checked for the field name.

## Honest-failure protocol

Adopted verbatim from M7, which this project learned the hard way when its
first fleet run was a 100 % harness artifact:

- The gate binary prints the bar and `exit(1)` on FAIL. A green terminal is not
  a PASS; the exit code is.
- A FAIL is diagnosed before it is re-run. Harness defects and genuine
  properties are separated and both recorded.
- A local run is **smoke**, never the gate. It proves the harness wires up; it
  does not produce the number, because a single box cannot show cross-host
  restart cost.
