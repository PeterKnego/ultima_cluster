# UC v2 M5 — SDK, apply path, protocol v2 IPC — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the service polls the shared log buffer in place (no apply ring), responses bypass the node via an egress broadcast ring, and the v1 trait contracts get a v2 backend — proven by the ported v1 correctness harness (WGL lincheck + partition scenarios + SIGKILL crashtest) and the headline gate: **client→apply→response ≥400k msgs/s @ p50 ≤1 ms, fsync on, 3×c6id**.

**Architecture:** M4's heap-side counters move into an mmap'd 4 KiB cnc page; the log buffer becomes file-backed; client submissions enter through a v1-style MPSC ring gated by the M3 admission window; the service is a sync polling agent that reads committed frames straight out of the mapped ring (one deliberate copy, seqlock-validated) and publishes responses onto a broadcast ring the node never touches; a lagging or restarted service degrades to direct read-only journal replay and rejoins the live buffer. Before any SDK work, three REQUIRED safety carries from the M4 final review land: the truncation-epoch protocol, first-block truncation support, and a sim mode that models the actual intake-gate mechanism.

**Tech Stack:** Rust (workspace, edition 2024), `uc_protocol` v2 (no_std layouts), `uc2_log`/`uc2_net`/`uc2_consensus`/`uc2_node`/`uc2_sim`, new crates `uc2_service` + `uc2_client`, v1 `uc_protocol` ring types (SPSC/MPSC/Broadcast, reused verbatim), `ultima_journal` (in-tree), `memmap2`, `fs2` (flock), `bincode` 2 (serde mode), `uc-lincheck` (WGL checker + RegisterSm, gains a `v2` feature).

## Global Constraints

Copied verbatim from the spec (`docs/superpowers/specs/2026-05-10…` conventions + `2026-07-09-uc-v2-aeron-shaped-smr-design.md`) and the M4 final review:

- **Headline gate (spec §9 M5 row):** full lincheck + crashtest green; client→apply→response ≥400 k msgs/s @ p50 ≤1 ms, fsync on (3×c6id fleet; local runs are core-starved smoke — report honestly, never retrofit).
- **Apply is sync, deterministic, no I/O, no clock, no randomness** — `fn apply(&mut self, position: u64, cmd: Self::Command) -> Self::Response`. Non-negotiable for SMR.
- **Reads are typed `Query`/`QueryResponse`, never closures.**
- **One deliberate copy at the apply boundary** (mapped ring → `Vec<u8>`/`Bytes`), seqlock-validated against `append`; borrowed views into an overwritable ring are unsound.
- **Commit means quorum-fsync'd.** The commit counter is written by exactly one agent (consensus). Every cnc counter has exactly one writer.
- **Commit is monotonic within-run ONLY** (M3/M4 restart contract): after a node restart the apply side must tolerate transient `commit < service_applied` (wait, never error) and always clamp to `min(commit, durable)`.
- **`uc_protocol` is no_std/core-only.** Layout constants + encode/decode only; atomics, mmap, I/O live above it.
- **Positions are absolute u64 bytes, monotonic forever.** Frame layout per `uc_protocol::v2::frame` (32 B header, 32 B alignment, atomic-after-write length).
- **`app_id` + `instance_id` + `protocol_version` checked at every IPC attach.** Mismatched app_id = wrong cluster; mismatched instance_id = node restart since attach; incompatible version = refuse.
- **v2.0 security posture:** trusted private network, no wire auth (stated decision). No new crypto.
- **clippy `--workspace -- -D warnings` and `--all-targets` for the uc2 crates must stay clean.** Denied in CI history: `manual_is_multiple_of`, `int_plus_one`, `collapsible_if` (use let-chains).
- **Journals/instance dirs never on `/tmp` for load runs** (RAM tmpfs, ~840 MiB quota on the dev box). Unit tests with tiny buffers may use `tempfile::tempdir()`.
- **Implementers stage ONLY their own files** (never `git add -A`); commit on branch `uc2/m5-sdk`.
- **M1–M4 code conventions hold:** single-writer counters with `store_release`/`load_acquire`, agents as `AgentRunner` polling loops returning made-progress, fail-stop via `Action::Fatal`/panic on invariant breach, honest gate binaries that `exit(1)` on FAIL.

## Decisions locked by this plan (resolving the sketch's open questions)

1. **Nonce plumbing for ReadIndex:** new datagram kinds `DGRAM_KIND_READ_PROBE=10` / `DGRAM_KIND_READ_PROBE_ACK=11`, 16-byte body `{nonce: u64, from: u32, reserved: u32}` — explicit `from`, no source-addr dependence. Handled entirely by the consensus agent (node side); the ElectionSm is NOT touched by reads.
2. **Queries flow through the node; submit responses do not.** Client → `query.ring` (MPSC) → node barrier → `svc_query.ring` (SPSC node→service) → service answers directly onto its egress broadcast. The task14 TOCTOU is closed **service-side**: the node stamps the epoch captured after the barrier into the forwarded query; the service answers only if its current epoch still matches (a restarted incarnation has a new epoch and refuses, client retries).
3. **Two broadcast rings** (single-writer each): `egress_service.broadcast` (service-written: all submit + query responses) and `egress_node.broadcast` (node-written: NOT_LEADER redirects + barrier RETRY). The client matcher polls both.
4. **`service_epoch` is a plain incarnation counter** (bump-once-at-attach, before READY), not an odd/even seqlock — all validated reads are single atomics; capture-recheck brackets suffice.
5. **v2 SDK traits are defined fresh in `uc2_service`** (positions, no snapshot methods — snapshots are M6 and this is our workspace; the trait grows then). `uc-lincheck`'s `RegisterSm` implements both v1 and v2 traits (feature `v2`).
6. **`uc2_client` is sync/blocking** (threads + channels, no tokio). The gate binary drives load through the same rings with its own pipelined correlation table (no per-op channel wakeups).
7. **Embedded mode** = `CncPage::heap(...)` + in-process service threads on the same `Arc<CncPage>`/`Arc<LogBuffer>`; the file-backed and heap paths share every code path above the `Region` backing. In-process tests run exactly the shmem code.
8. **Legacy M3 sender/receiver modes are deleted**, and `m2_gate`/`m3_gate` are retired with them (measurement docs + git history are the record; m5_gate supersedes as the fleet tool).
9. **Node restart invalidates attachments (v2.0):** the cnc file is re-created on node start with a fresh `instance_id`; services and clients detect the mismatch and must re-attach. Live re-attach polish is M6. The log-buffer FILE is reused on restart (`open_file`), which preserves ring bytes below durable across restarts for free.
10. **Service liveness = heartbeat timestamps in cnc** (node and service each stamp `*_heartbeat_ns` once per duty cycle). No shared flock probe — v1 documented one but never implemented it; v2 stays heartbeat-only, stated honestly.
11. **`AppCommand = Bytes` is satisfied at the transport layer, serde at the trait boundary** (v1 semantics kept): payload bytes flow ring→frame→apply with exactly the one deliberate copy and are bincode-decoded once, at the apply boundary. The node never inspects payloads. The typed `Command`/`Response` associated types are the v1 trait contract the spec says to keep.

### Task 1: Truncation-epoch protocol + consensus/node hardening sweep

The M4 final review's REQUIRED carry #1 plus the accepted-for-M4 residual it must close: *"stale-ack premature open + stale map persist after mid-flight adoption"*, expanded with consensus-level ack identity, an infallible ack channel, and persist-map-BEFORE-truncate ordering. Also folds the small M4 carries: symmetrize RequestVote membership into the SM, `become_leader` resets `last_gossip_ns`, hard-assert timeout config sanity, per-kind NetEvent drop stats, and the doc softenings (receiver resync "only truncation" overclaim; sender `overruns` meaning).

**Files:**
- Modify: `uc2_consensus/src/election.rs`
- Modify: `uc2_node/src/node.rs`
- Modify: `uc2_net/src/receiver.rs` (doc comment only), `uc2_net/src/sender.rs` (doc comment only)
- Tests: inline `#[cfg(test)]` in `election.rs` and `node.rs`

**Interfaces:**
- Consumes: M4's `ElectionSm::step`, `Event::Truncated{to}`, `Action::Truncate{to,new_map}`, node-side `pending_new_map`, archive agent truncate command channel.
- Produces: `Event::Truncated { epoch: u64, to: u64 }` (SM event gains epoch); node-side `TruncationSlot` (the infallible ack slot, defined below) used by the archive agent; SM behavior change: **the truncating latch is held across term adoption** and released only by the matching-epoch ack.

**Design (implementer follows exactly):**

The node stamps every issued truncation with a monotonically increasing `truncation_epoch: u64` (node-side field in `Consensus`, starts 1). The archive agent's ack channel is replaced by a single slot that cannot drop:

```rust
/// Single-slot truncation ack. One truncation is in flight at a time (the SM
/// latch serializes them), so a slot suffices and, unlike a bounded channel,
/// cannot drop an ack (M4 final-review carry: infallible ack send).
#[derive(Clone, Default)]
pub(crate) struct TruncationSlot(Arc<Mutex<Option<(u64, u64)>>>); // (epoch, to)
impl TruncationSlot {
    pub fn post(&self, epoch: u64, to: u64) { *self.0.lock().unwrap() = Some((epoch, to)); }
    pub fn take(&self) -> Option<(u64, u64)> { self.0.lock().unwrap().take() }
}
```

Ordering change on `Action::Truncate{to, new_map}` (node `exec`):
1. `state.store_term_map(&new_map)` — **persist the pruned map BEFORE the physical truncate** (durable on return). With `rederive_term_map` this ordering is self-healing across a crash between the two steps: boot re-derives any data-stamped entries the pruned map is missing, and a pruned-map-persisted-but-not-truncated journal is corrected by the reconcile that reissues the truncate.
2. `self.truncation_epoch += 1; self.pending_truncation = Some(self.truncation_epoch);`
3. Send `(epoch, to)` to the archive agent (existing command channel gains the epoch field).

Archive agent: after `archive.truncate_to(to)` + counter prime, `slot.post(epoch, to)`.

Consensus duty-cycle step 1c becomes: `if let Some((epoch, to)) = slot.take()`:
- `epoch != self.pending_truncation.unwrap_or(0)` → **stale ack**: feed `Event::Truncated{epoch, to}` anyway (the SM's durable-min clamp still applies — physical truncation is truth) but do NOT reopen the gate, do NOT clear `pending_truncation`.
- matching epoch → clear `pending_truncation`, feed `Event::Truncated{epoch, to}`, then reopen the gate **only if** `!self.awaiting_reconcile` (a term adopted mid-truncation means a fresh reconcile in the new term must complete first; the leader's 100 ms map floor guarantees it arrives).

SM change (`election.rs`):
- `Event::Truncated{epoch, to}`: keep the existing `durable = durable.min(to)` before everything. Release the `truncating` latch only when the node fed a matching-epoch ack — since the node filters, the SM can simply trust the event, BUT to keep the SM self-contained the epoch is carried in the event and the SM stores `truncating_epoch: Option<u64>` set from a new field on `Action::Truncate`. Concretely: `Action::Truncate { epoch: u64, to: u64, new_map: … }` — the SM allocates the epoch itself (`self.truncation_epoch += 1` inside the SM, node mirrors it from the action), and `Truncated{epoch,..}` releases the latch iff `Some(epoch) == self.truncating_epoch`. This removes the node/SM split-brain on identity entirely: **the SM owns the epoch, the node transports it.**
- `adopt_term` (mid-truncation): NO LONGER clears `truncating`/`truncating_epoch`. The latch (allow-list {RequestVote, Vote, Truncated}) stays until the matching ack. `awaiting_reconcile` handling stays node-side.
- `handle_request_vote`: add the membership check `if !self.members.contains(&from) { return; }` (symmetry with Vote grants — M4 Info finding).
- `become_leader`: add `self.last_gossip_ns = now_ns;` (M-4).
- `ElectionSm::new`: `assert!(cfg.election_timeout_min_ns < cfg.election_timeout_max_ns, "election timeout span empty");` (M-2 hard-assert; release-mode wrap gone).

Node sweep in the same task:
- `awaiting_reconcile` restructure (M-3): set on term adoption; cleared on clean reconcile (gate reopen), on matching-epoch ack when no adoption intervened, and on `BecomeLeader`.
- NetEvent drop stats: replace the single `net_event_drops` counter with per-kind counters `net_drops: [AtomicU64; 6]` indexed by a `NetEvent::kind_idx()` helper; `net_event_drops()` sums them (public API unchanged) and a new `net_event_drops_by_kind() -> [u64; 6]` is added.
- Doc softenings: receiver `resync_after_truncation` doc says the signature also fires on BecomeLeader prime (harmless-to-beneficial), not "only truncation"; sender `overruns` doc states it counts NAKs unservable from ring AND journal (purged or no replay source).

### Task 2: First-block truncation support

M4 carry #3 (REQUIRED): a contested first election reaches `Archive::truncate_to` with a cut at/inside the first archived block → today `UnsupportedTruncation` → fail-stop **panic loop on every restart** (permanent single-node loss). Fix: `Journal::truncate_all()` + the archive path that clears everything and re-appends the surviving prefix.

**Files:**
- Modify: `ultima_journal/src/journal/mod.rs` (add `truncate_all`)
- Modify: `uc2_log/src/archive.rs` (`truncate_to` first-block arm; delete the `UnsupportedTruncation` error variant entirely — it becomes unreachable)
- Test: inline in both files + `uc2_node/tests/failover.rs` (one new scenario)

**Interfaces:**
- Produces: `Journal::truncate_all(&self) -> Result<Notifier, JournalError>` — removes every record; `first_seq()`/`last_seq()` return `None` after; crash-safe via the same intent-file discipline as `truncate_after` (an intent with `keep_seq` semantics of "keep nothing": write intent, unlink all segments, create a fresh empty segment at base_seq 0, remove intent; `Journal::open` completes a torn `truncate_all` idempotently — reuse the existing intent machinery with a reserved keep_seq sentinel `u64::MAX` meaning keep-none, and extend the open-time intent replay to handle it).
- Produces: `Archive::truncate_to(pos)` handles `pos` at/inside block 0: read the surviving prefix bytes `[first_base, pos)` from block 0 **before** clearing, `journal.truncate_all()`, then if `pos > first_base` re-append the prefix as a new block seq 0 with meta `first_base` and fsync. `next_block_seq`, `durable_pos`, `last_observed_term`, `term_observations` reset accordingly.

`next_batch` contract (implementer follows exactly): if `cursor >= target` → `CaughtUp`. Call `read_run_validated(cursor, min(64 KiB, remaining), buf)`. `Overrun` → `Overrun` (caller degrades to journal). `NotCommitted` → `CaughtUp`. `Run{bytes, advance}` → iterate frames in `buf[..bytes]`; a frame whose END exceeds `target` ends the batch there (cursor advances only to that frame's start; the guard matters because `read_run_validated` bounds by `append`, not by commit); otherwise cursor += advance.

```rust
fn apply_cycle<S: StateMachine>(st: &mut ApplyState<S>) -> bool {
    let c = st.cnc.counters();
    let target = c.commit.load_acquire().min(c.durable.load_acquire());
    let mut progressed = false;
    loop {
        match st.follower.next_batch(target) {
            Batch::CaughtUp => break,
            Batch::Overrun => { st.needs_replay = true; break }  // Task 9 wires the replay
            Batch::Frames(frames) => {
                let mut sm = st.sm.write().unwrap();
                for (pos, hdr, payload) in frames {
                    if hdr.frame_type != FRAME_TYPE_MESSAGE { continue } // NEW_TERM skipped
                    if Some(pos) <= sm.last_applied() { continue }       // idempotent re-entry
                    let cmd: S::Command = decode(payload)
                        .expect("corrupt committed frame (fail-stop)");  // bincode; committed bytes are trusted
                    let resp = sm.apply(pos, cmd);
                    if st.is_leader() { st.egress.publish(hdr.session_id, hdr.correlation_id, pos, &resp); }
                }
                drop(sm);
                st.cnc.service().service_applied.store_release(st.follower.cursor);
                progressed = true;
            }
        }
    }
    st.cnc.status().service_heartbeat_ns.store_release(unix_ns());
    st.drain_queries(); // Task 11 fills this in; no-op stub here
    progressed
}
```
